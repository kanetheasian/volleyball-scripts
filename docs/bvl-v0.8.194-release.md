# BVL Assist v0.8.194

Normal Auto Set now learns native Set activation separately from the subsequent wait for ball contact. Only an accepted request's own newly tagged Set hitbox trains activation; observations are per character and grounded/airborne front/back mode, bounded, recent and median filtered. Legacy contact-lead observations remain available for diagnostics and callers without activation telemetry. Reload preserves compatible activation observations.

This release also includes the previously local antenna illegal-hit zone overlay, which uses each court's native antenna offset, and the numeric jump-speed factor from 1 to 4. The native blocking-mode shadow repair preserves the selected mode. Charge and windup timing follow the multiplier while native jump power and flight physics remain unchanged. Receive/Set action cancellation and sprint controls from v0.8.189 are retained.

Late rescues recompute the native hand pose at the same time as their incoming ball forecast. Changed airborne commands also use measured native replication delay, less the remaining activation time, when deciding whether the tilt has settled. The final overlap still takes priority over waiting. A short character-scoped history of actual local hand positions replaces the constant-speed rewind when the forecasted replicated hand lies in already observed time. Replication-delay measurement can fit that recorded path too. Future forecasts and missing historical brackets retain their previous bounded kinematic fallback.

The user's deeper CenterCourt arrangement is Receive root (-10, 3, 46), P1, and Spike root (18, 14, 3), P15, with the Spike sphere centered at (18, 15.5, 3). The user selected 4x jump speed during this investigation; final validation preserved that setting, Normal/Medium, jump height 1.15 and the entire current configuration. Both bots' original pivots and attributes remained unchanged, with Spawn false after testing.

The v193 baseline on ball 295 predicted 19.55 studs but contacted the spike bot at 16.76. The planned native action lead was 0.216 seconds while request-to-contact was about 0.080 seconds. Separating activation improved delivery, but intermediate v194 builds still showed low or missed contacts (including 331 at 16.91 and missed 330/335). A captured low contact used a replicated tilt of about 12.7 degrees after a new 16.2-degree command had been held for only 0.041 seconds. Settling alone improved height but retained an above-bot miss. The final recorded-hand forecast accounts for the fast takeoff's changing motion rather than extrapolating it backward at the latest velocity.

Final live build: three consecutive controlled one-ball trials, 337–339, all confirmed a native Set/SetBack followed by the intended bot Spike and recorded “Target spike cleared net.” Spike contact heights were 18.5171, 19.3850 and 19.4407 studs. Incoming vertical speeds, derived from the replicated outgoing Set velocity and packet flight duration at ball gravity -25, were -20.0505, -15.3623 and -17.4470 studs/second. Each trial created exactly one ball. Runtime errors were empty. Configuration comparison was recursive, so reloaded selection tables were compared by contents rather than identity.

Validation: full regression passed, including 652 runtime checks, 403 core checks, 25 native-pose checks, 22 startup/settling checks, 72 upper-bot rescue checks, 92 existing bot-height checks and 231 third-touch checks. Preview runtime passed 62 checks. Bundle compilation passed at O0 (773,340 bytes) and O1 (731,660 bytes).

These are current private practice-bot results, not new ranked/player-target validation or a guarantee for every geometry. Final trial 337 still had a 3.39-stud ball-origin forecast error before its successful upper-band contact. Existing lower contact saves remain available when the bounded upper search cannot find a delivery. Rerun the existing loader to fetch this version; a running script does not update itself.
